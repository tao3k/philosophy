* 问题
:PROPERTIES:
:CUSTOM_ID: philosophy.reflection.30.200-human-agent-design-triad-cn
:END:
当一句话可以完成订票，而写代码、做设计仍需要画布、文件、差异和运行结果，我们应怎样摆脱“所有
界面都会消失”与“AI 只是界面里的新功能”这两种相反却同样狭窄的想象？人、Agent 与设计应怎样
形成新的关系，哪些地方该少，哪些地方反而应该更充分地出现？
* 论证
界面与自然语言不是争夺唯一入口的两种产品形态。它们与 Agent 行动分别承担当事情被表达、被执行、
被看见和被共同修改时的不同需要；问题在于怎样组合，而不是先宣布谁取代谁。
** 传统对象与适用边界
传统 APP 把界面当作能力目录。按钮、菜单、窗口和页面既告诉人系统能做什么，也规定人怎样一步步
完成。设计对象主要是直接操作的 Human；好设计让功能可发现、操作可学会、状态有反馈。

这些经验没有因为 AI 出现而全部失效。人的视觉可以并行察觉位置、结构、比例和差异；一个稳定的
画布还能成为多人共同指认、讨论和修改的对象。传统思维的边界在于，它把“必须由人看见”和“必须
由人逐步操作”绑在了一起，也把软件预先划分的功能当作人的自然起点。
** 对象变革
现在，目的可以先以自然语言出现，Agent 把它翻译成搜索、工具调用和跨服务动作。人在很多事务中不再
需要浏览能力目录：说清出发地、时间、预算与在意之处，Agent 就能查票、比较、沟通客服并预约。

但另一些活动不是“把已经知道的目的交给系统执行”。写作、编程、绘画、建筑和研究会在行动中形成
问题；人需要同时看见多个对象，直接改变其中一处，观察整体怎样回应。这里可视化不是操作负担的
包装，而是思考和创造发生的场所。Codex 式工作也不只是一段对话：文件树、代码、diff、终端、测试
和 review 让人和 Agent 围绕同一个正在变化的作品思考。

对象因此不是从 Human 简单换成 Agent，而是形成三者关系：人带来目的、经验、判断和审美；Agent
理解语境、展开可能、协调能力并执行；设计组织两者共同看见、共同改变和相互校正的空间。这里的
“设计”不是第三个人格，而是这段关系赖以成立的形式。
** 判断
当前判断是：未来交互既不是 GUI-first，也不是 chat-only，而是按认知与行动需要在语言、代理行动和
可视化共同对象之间流动。自然语言常是表达目的最快的入口，Agent 常是跨系统执行最省力的承担者，
可视化常是比较复杂关系、直接塑形、共同审阅和保持长期上下文最快的方式。

“哪些该少”不能由极简审美单独决定；应减少的是与人的目的无关的操作负担。“哪些该多”也不能由
功能堆叠决定；应充分出现的是有助于人形成判断、发现差异、感受作品、理解后果和与他人共同工作的
内容。留白与丰富不是敌人：留白让无关之物不占据生活，丰富让真正值得看的事物不被压扁。

#+NAME: human-agent-design-roles-cn
#+EXPLANATION: 三者不是固定分工，而是根据任务怎样形成目的、怎样改变现实和怎样接受判断来重新组合。
| 关系位置 | 更适合承担什么 | 不应被迫承担什么 | 需要从另外两者得到什么 |
|----------+----------------+------------------+--------------------------|
| 人 | 形成和改写目的，感受取舍，作审美与伦理判断 | 记住每个入口、重复填表、监控全部执行细节 | Agent 承担繁琐，设计让关键关系可见可改 |
| Agent | 理解话语、搜索、转换、协调、提出候选和执行托付 | 假装已经穷尽人的目的，独占解释与授权 | 人给出可撤回的方向，设计提供清楚状态与共同对象 |
| 设计 | 组织注意、并置差异、形成可操作共同物、连接行动与后果 | 固定所有流程，或用视觉装饰掩盖权力 | 人的经验修正形式，Agent 的能力按需进入而不占满 |

** 少掉什么，多出什么

可以少掉的，是为了软件内部结构而存在的导航：在多个 APP 间切换、重复登录、寻找功能、把同一资料
填进不同表格、等待客服电话、追踪散落通知。它们可以由 Agent 静默处理，只有异常和真正分岔回来。

应该保留甚至更充分出现的，是人凭直觉和经验能够更快把握的关系：地图上的远近、时间轴上的冲突、
代码 diff 的具体变化、画布上的比例、多个方案并置后的气质、预算与日程的联动、多人共同修改留下的
痕迹。Agent 可以生成和解释这些可视对象，却不应把它们全部压回一段线性文字。

#+NAME: interaction-form-by-work-cn
#+EXPLANATION: 交互形式跟随工作的性质；“最快”不是一个媒介永远获胜，而是不同媒介在不同认知动作中接力。
| 工作性质 | 自然语言的价值 | Agent 行动的价值 | 可视与直接操作的价值 |
|----------+----------------+-------------------+------------------------|
| 目的明确的事务，如订票 | 快速说出约束与在意之处 | 搜索、比较、沟通、填写、付款前准备 | 在关键取舍或异常时显示少量候选与后果 |
| 日程与多人协调 | 说出关系、优先级和不能交换的承诺 | 求交集、联系、等待回复、维护草案 | 时间轴同时显示冲突、空隙与谁承担改变 |
| 写代码 | 描述问题、意图与验收条件 | 搜索代码、编辑、运行测试、解释失败 | 文件、diff、终端和 review 形成可检查作品 |
| 做视觉设计 | 描述情绪、用途、参照与尚未成形的想法 | 生成变体、整理素材、执行重复修改 | 画布、比例、颜色和空间需要并置观看与直接塑形 |
| 长期生活思考 | 说出故事、迟疑和价值冲突 | 整理线索、寻找现实入口、记住经同意的关系 | 只有在能帮助理解时呈现路径和比较，不把人生画成仪表盘 |

** 一种新的交互节奏

新设计不应先选择“做一个聊天界面”或“做一个可视化工作台”，而应观察事情怎样展开。它可以从一句
话开始，由 Agent 安静行动；遇到需要比较的分岔时形成一张临时的可视对象；人直接修改或批注；Agent
再带着修改继续执行；完成后只留下可带走的作品、决定和凭据。界面可以因事出现，也可以在事情结束
后收起。

这种节奏比永久 APP 更接近工作本身。它不要求所有能力一直可见，也不把所有过程永远隐藏。设计的
任务是让合适的形式在合适的时候出现，并在它不再帮助人时收敛。
** 论证与辩论场景
两派争论需要进入具体工作，才能避免“自然语言万能”或“可视化永远最快”都变成口号。可视化对于
并行关系和共同作品常常最快，自然语言对于目的和例外常常最快，Agent 对重复执行常常最快；每一种
“最快”都有不适用的地方。

#+NAME: triadic-interaction-debate-cn
#+EXPLANATION: 场景不预设哪一派获胜，而是检验三种关系怎样组合才真正减少负担并保留思考。
| 场景 | 支持当前判断的理由 | 反方理由 | 会改变判断的证据 |
|------+--------------------+----------+------------------|
| 一句话购买机票 | 目的明确，Agent 能吸收绝大多数操作 | 完全隐藏会遮住时间、价格和退改取舍 | 多数普通行程无需浏览 APP，关键分岔的一页比较足以让人理解 |
| Codex 协作写代码 | 对话给方向，Agent 执行，diff 与测试让作品可检验 | 熟练开发者有时直接编辑更快，对话也会打断心流 | 人能在代码、运行结果和对话之间自由切换，且错误更早被发现 |
| AI 辅助视觉设计 | Agent 快速产生候选，画布支持感受和塑形 | 过多候选会挤压审美形成，模型风格会趋同 | 人能留下自己的痕迹、减少候选并直接改变结构，而非只挑成品 |
| 家庭日程安排 | 语言表达关系，Agent 协调，可视时间轴揭示负担 | 可视图也可能把情感承诺简化成色块 | 参与者既能讲述原因，也能共同看见时间后果并修改安排 |
| 无障碍场景 | 语音和 Agent 可绕过难用 GUI | “可视化最快”排除了不能看或不以视觉为主的人 | 同一共同对象能通过视觉、语音、触觉和结构化控制等价进入 |

如果未来证据显示，在创作与复杂判断中，纯对话能稳定提供并行感知、精确操控和共同指认，而不增加
记忆负担，这一判断应被修正。反过来，若可视工作台不断迫使人管理工具而没有改善作品理解，也不应
因为它看起来专业就保留。
** 原则与治理边界
本文只提出“交互形式应随认知与行动需要组合”的 Reflection 判断。它没有规定所有产品必须有多少
可视化，也没有把“三者关系”升成 Charter Principle。若未来形成原则，需要另行说明适用范围、无障碍
要求、反例和失败方式。

Governance 则决定谁能用哪些生活和工作证据修改标准、如何避免视觉设计师或模型提供者独占定义、
以及怎样处理商业目标让界面故意变多或故意隐去的冲突。内容判断与准入治理仍需分开。

* 反例
第一，“可视化永远最快”过于绝对。视觉会过载，也会排除视障者；线性语言在讲故事、解释动机和处理
含糊时反而更自然。这里保留的是多种可感知、可直接操控的共同对象，不是视觉霸权。

第二，纯自然语言有时比临时生成界面更轻。为一个简单确认绘制复杂面板，会把旧 APP 重新造回来。

第三，三者关系可能成为把所有产品都做得更复杂的借口。若一个动作已经得到清楚授权、可逆且没有
实质分岔，Agent 安静完成并给简短回执就够了。

第四，人也可能希望直接沉浸在工具中，不想让 Agent 插入。新的体系必须允许人绕过 Agent；否则
“协作”只是另一种强制中介。
* 暂定结论
AI 不会简单终结界面，而会终结“每种能力都必须先变成人工操作页面”的前提。订票这类目的明确的
事务可以主要由语言和 Agent 完成；代码、设计和复杂协作仍需要一个可看、可改、可共同指认的作品空间。

人、Agent 与设计的三者关系，让交互不再围绕 APP 组织，而围绕事情怎样被理解、完成和重新判断组织。
该少的是对软件结构的服从，该多的是对真实关系、作品差异和生活后果的感知。好的美学不是一律空，
也不是一律丰，而是让必要之物充分出现，让无关之物自然收敛。
* 仍需面对的问题
仍需从游戏、音乐、建筑、医学影像、数据分析、维修与照护等场景继续检验：哪些共同对象不能被语言
替代，哪些可视传统只是职业习惯，Agent 生成界面是否会造成不稳定和学习困难，以及怎样让临时界面
仍具可访问性、一致性与可信状态。

还需要面对审美权力：谁决定什么值得多看，谁把自己的极简风格称作留白，谁把信息密度称作专业；
当 Agent 为每个人生成不同界面时，人们是否还拥有可以共同讨论和争议的公共形式。
