* 原则
:PROPERTIES:
:CUSTOM_ID: cross-repository-principle-cn
:END:

本映射把七项专题原则投影为工程审查条件。它不把当前仓库结构永久化：实现可以在不改变
哲学语义的前提下替换；如果规范含义发生变化，则必须回到对应 Charter 的生命周期重新审议。

专题入口：[[file:../10-charter/10.10-epistemology-and-uncertainty.org][认识论与不确定性]]、
[[file:../10-charter/10.20-temporality-and-causality.org][时间与因果]]、
[[file:../10-charter/10.30-human-agency.org][人的能动性]]、
[[file:../10-charter/10.40-action-and-authority.org][行动与权限]]、
[[file:../10-charter/10.50-proportional-assurance.org][比例证成]]、
[[file:../10-charter/10.60-resilience-reversibility-optionality.org][韧性、可逆性与选择权]]和
[[file:../10-charter/10.70-practical-learning.org][实践学习]]。

* 规范要求

| 原则 ID | 稳定工程要求 | 不可接受的替代 |
|---------+--------------+----------------|
| PHIL-EPI-001 | 保存来源、观察、推断和未知边界 | 把模型置信或流畅表达当作事实 |
| PHIL-TEMP-001 | 区分事件时间、观察时间、顺序和因果主张 | 由相关性或日志顺序直接推出因果 |
| PHIL-AGENCY-001 | 保存人的意图、拒绝、覆盖与申诉能力 | 以优化指标代替人的价值和同意 |
| PHIL-AUTH-001 | 行动前证明主体、范围、时效与政策授权 | 把工具可用性当作行动权限 |
| PHIL-ASSURE-001 | 证成强度随不可逆性、影响半径、不确定性和权限范围提高 | 所有行动共享单一置信阈值 |
| PHIL-RESIL-001 | 优先可回滚、隔离、降级、观察和保留选择权 | 只证明成功路径 |
| PHIL-PRAXIS-001 | 让行动结果通过 receipt 与复验返回知识系统 | 把执行返回码当作学习闭环 |

测试、Scenario、proof 或 receipt 才能把候选状态推进为“已验证”。

| 仓库/系统 | 候选职责 | 当前证据状态 | 下一证据入口 |

| MRR | semantic identity、typed relation、lineage、query、transition、IMPACT 与 admission | 局部机制存在；原则符合性待证明 | 关系、代际、查询与 admission receipt |
| mrr-data | Arrow / GraphAr、snapshot、物理持久化与分发 | 候选；仅为物理数据平面，不产生语义权威 | snapshot / persistence / distribution receipt |
| ASP / ASP Rust | agent 协议、authority、Scenario 宏与性能门 | 局部机制存在；原则符合性待证明 | Scenario receipt 与 benchmark |
| Marlin | policy、decision 与 intervention 边界 | 候选；需项目 receipt | 权限拒绝和降级测试 |
| Aitia | causal assurance：claim、assumption、evidence、obligation、invalidation、verification planning 与 SDLC / ADR / GitOps assurance | 候选；需项目 receipt | obligation、verifier evidence 与 invalidation receipt |
| Episteme | 垂直领域 meaning、ontology、relation、policy、source、Scenario / Profile / Case 与 qualification metadata | 候选；需项目 receipt | 领域语义与 qualification receipt |

* 审查问题

审查者必须逐项回答：引用了哪个 Principle ID；该实现保存了什么语义；哪些内容只是候选；
证据在哪里；反例或失败会如何使声明失效；实现替换是否保持规范含义；若改变规范含义，
是否已经通过 challenge / Reflection 证据回到 Charter，并形成 retained、revised、superseded
或 withdrawn 的明确决定；challenge 是事件与证据，不是 Principle status。
