* AI 交互对象变革专题

这个专题不把传统 GUI 规范直接延长成 Agent 时代的答案。它分别审视三种已经不同的对象：人直接
操作软件；人与 AI 共同形成行动关系；Agent 成为服务的直接调用者，而人和其他受影响者处在目的、
授权、后果与申诉的位置。传统标准只作为历史基线，不能自动成为新对象的标准。

专题文档同时组合普通 Reflection 合约与 =philosophy.ai-object-reflection.cn.v1=。合约要求每篇写出
传统对象及适用边界、对象变革、当前判断、支持与反方共同出现的场景，以及 Principle 与 Governance
的边界。它约束反思的完整性，却不把暂定判断提前升成原则。

| 专题入口 | 要面对的变革 | 当前判断 | 辩论场景 |
|----------+--------------+----------+----------|
| [[file:30-reflections/ai-object-shift/30.180-beyond-gui-user-space.org][GUI 之后仍需看见什么]] | APP 从人的主要操作入口变成 Agent 可调用的服务；对象从 human 变成 human-with-AI、agent 与 affected-human | 可以隐去操作负担，不能隐去目的、重要后果、授权、失败和接管 | 一句话订票、代理订餐、日程协调、Agent-to-Agent 交易 |
| [[file:30-reflections/ai-object-shift/30.190-when-services-face-agents.org][当服务面对的是 Agent]] | 服务直接面对 Agent，但后果落在委托人、受影响者、劳动者与制度 | Agent 可以是直接对象，不能是唯一设计主体 | 航司接口、餐厅来电、日历协商、购物议价、公共服务 |
| [[file:30-reflections/ai-object-shift/30.200-human-agent-design-triad.org][人、Agent 与设计]] | 语言、代理行动与可视共同对象重新组合，不再由永久 APP 统领 | 该少的是操作负担，该多的是形成判断、作品和共同理解所需的内容 | 订票、Codex 写代码、视觉设计、家庭日程与无障碍 |
